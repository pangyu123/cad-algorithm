# OCCT 7.8.1 圆角识别算法：28 轮迭代技术详解

本文用于解释 28 轮迭代中每个技术点为什么需要、采用了什么方法、解决了什么问题，以及仍有哪些边界。它是面向算法理解的说明文档；工程路径、运行方式、性能数字和后续接手流程见仓库根目录的《圆角识别算法基线与28轮迭代记录.md》。

## 一、先理解算法的分层结构

圆角识别不是简单判断“这个面是不是圆柱面”，而是逐层建立证据：

```text
TopoDS_Shape
   ↓
逐面几何判断：这个面像不像圆角面？
   ↓
支撑判断：它是否连接两个结构母面？
   ↓
Link：两个候选圆角面能否连接？
   ↓
Chain：哪些候选面属于同一个连通分量？
   ↓
Path：在闭环或分叉图中拆出可遍历路径
   ↓
Feature：把多条路径聚合成工程意义上的完整圆角特征
   ↓
R(s)、方向连续性、三态证据、真值和性能评测
```

核心术语：

- **支撑面**：圆角两侧被过渡连接的结构面，例如箱体的顶面和侧面。
- **G1 连续**：两曲面交界处切平面连续，视觉上没有明显折角。
- **主曲率**：曲面某点最大和最小的两个法向弯曲程度；局部半径约为曲率绝对值的倒数。
- **圆角脊线方向**：圆角沿长度延伸的方向，不是跨过圆角截面的方向。
- **Chain**：候选面连接图的一个连通分量。
- **Path**：连通图中的最大非分支路径；一个分叉 Feature 可以包含多条 Path。
- **Feature**：调用方更关心的完整圆角语义，例如单面圆角、简单链、闭环和复合分叉网络。
- **R(s)**：半径随路径归一化弧长参数 `s` 的变化序列。

## 二、第一阶段：建立基本识别能力

### 第 1 轮：工程集成、诊断和标准曲面恢复

**问题**：原始算法主要依赖明确的圆柱、圆环和球面类型。CAD 交换后，一个几何上接近圆柱的面可能变成一般 BSpline，或携带异常容差和退化拓扑。

**方法**：

- 保持原始“识别圆角.cpp”不变，通过适配器做 A/B；
- 检查 BRep 有效性、模型尺度、容差、退化边和非流形边；
- 根据模型尺度与 BRep 原始容差计算有效线性容差；
- 使用 OCCT canonical recognition 从一般曲面恢复圆柱或球面；
- 候选面必须有两个不同的切向支撑面；
- 记录逐面来源、半径、拟合 gap、支撑和拒绝原因。

**效果与边界**：CrankArm、Motor、hammer 出现了原算法没有的候选；同时发现 bottle 中的大半径主体曲面可能误报。这一轮证明标准曲面恢复能增加候选召回，但没有真值时不能称为准确率提升。

### 第 2 轮：BSpline/Bezier 曲率场候选

**问题**：工业圆角经常已经变成自由曲面，不能只依赖 `GeomAbs_Cylinder` 等解析类型。

**方法**：在曲面参数域网格采样两个主曲率，选择横截面主导曲率并统计局部半径；使用半径变异系数、次/主曲率比过滤不像 canal surface 的曲面。同时根据面积、圆柱角覆盖和半径/模型尺度识别主体曲面风险。

**效果与边界**：找到了 CrankArm、Pump、Motor 中的自由曲面候选，并过滤了 bottle 的可疑大主体面。此时只得到“像圆角的自由曲面”，仍需要支撑关系和链路证据。

### 第 3 轮：导入断裂后的几何支撑恢复

**问题**：IGES 导入后，几何上相邻的面可能没有共享 `TopoDS_Edge`，导致真实圆角因缺少拓扑支撑被拒绝。

**方法**：用包围盒邻域做预筛，再在边界采样、向相邻曲面投影，检查空间 gap、UV 裁剪域、法向与切向关系；加入每面和每模型计算预算。候选图开始分解为开放路径、闭环和分叉路径。

**效果与边界**：bearing IGES 从 0 增至 41 个候选，hammer IGES 从 0 增至 15 个。几何恢复结果置信度较低，因为“空间接近且相切”仍可能是偶然关系。

### 第 4 轮：确定性几何指纹和审计报告

**问题**：只有候选数量无法回答为什么接受、为什么拒绝，也无法稳定比较两次运行。

**方法**：加入量化包围盒、质心、面积、半径和曲面类型构成的 `persistent_id`；导出 faces、links、chains、paths、DOT、accepted-faces BREP 和真值模板。

**效果与边界**：多个模型重复运行的报告和 BREP 哈希完全一致，建立可复现回归闭环。`persistent_id` 是评测用几何指纹，不是跨大幅重参数化、修复或缩放的永久实体 GUID。

## 三、第二阶段：复杂链、分叉与 Feature 语义

### 第 5 轮：外部结构支撑和伪复合连接清理

**问题**：旧逻辑可能把另一个圆角面当作结构母面，导致两个候选因“共同拥有两个圆角邻面”被错误补链。

**方法**：区分全部切向邻面 `supportFaceIds` 和非候选结构面 `externalSupportFaceIds`。无共享边的复合连接只允许使用两个共同外部结构支撑面；支撑不足的链标记为需要复核。

**效果与边界**：bottle 删除 48 条伪复合连接，路径从 105 降至 25而三个主要连通 Feature 保持。路径减少本身不是准确率证明，但这次删除有明确的错误连接根因。

### 第 6 轮：TopologyRole 与 Feature

**问题**：Path 是图遍历片段，不等于一个 CAD 圆角。一个真实角部网络可能被拆成很多 Path。

**方法**：把已接受圆角面作为图节点，把实际进入图的 Link 作为边。按节点的唯一邻居数量定义：

```text
degree = 0  → IsolatedPatch
degree = 1  → TerminalPatch
degree = 2  → BandPatch
degree > 2  → JunctionPatch
```

再把整个连通分量聚合为 `IsolatedPatch`、`SimpleChain`、`ClosedLoop` 或 `CompositeJunctionNetwork` Feature。

**效果与边界**：bottle 的底层 25 条 Path 被解释成 3 个工程 Feature。角色首先是图角色，不是曲面类型，也不直接证明建模历史。

### 第 7 轮：双曲率角部面与几何—拓扑一致性

**问题**：三条带状圆角在角部汇合时，补片通常在两个主方向都明显弯曲，旧的“次曲率较小”规则会将其排除。

**方法**：增加两个主曲率均显著且大部分采样点同号的双曲率模式；Junction 期望球面、恢复球面或双曲率几何，Band 期望圆柱、圆环或单主曲率自由曲面。

**效果与边界**：bottle 的汇合面几何角色通过，bearing 中两个高图度但仍呈带状几何的面被标记冲突。统计阈值仍需真实角部真值校准。

## 四、第三阶段：方向连续性证据

### 第 8 轮：公共边中点的脊线方向

**问题**：两个面相邻且半径相似，不代表它们沿同一圆角方向延伸。

**方法**：在公共边中点计算两侧次曲率主方向，以 `abs(directionA · directionB)` 判断无向共线性；默认阈值为 `cos(15°)`。Feature 只统计真正 `usedInGraph` 的 Link。

**效果与边界**：bottle 和 CrankArm 的活动共享边连接近似完全对齐；未进入最终图的低对齐邻接不再污染 Feature。

### 第 9 轮：沿公共边多点采样与脐点保护

**问题**：长边中点正常，不代表整条边都没有局部扭转。

**方法**：默认取 5 个内部样本，统计最小值、均值、标准差和覆盖率；两个主曲率接近时主方向不稳定，这类近脐点样本跳过。有效结论默认要求至少 60% 覆盖。

**效果与边界**：局部单点方向冲突不会被均值掩盖，覆盖不足会保持未知而不是假装通过。

### 第 10 轮：无共享边连接的投影方向

**问题**：IGES 几何恢复连接没有公共边，因此共享边方向证据覆盖不到。

**方法**：从一个面的裁剪边界采样并投影到另一个面；检查 gap、目标 UV 是否位于修剪域、曲率和脐点，再比较主方向。

**效果与边界**：bearing 的 6 条复合 Link 获得方向证据，其中 face 45–67 出现近垂直样本。算法保留连接并降置信度，没有凭单点直接断链。

### 第 11 轮：异常样本的 XYZ/UV 定位

**问题**：只有 alignment 和 gap 不能判断冲突来自错误投影、参数分支还是实际曲率方向变化。

**方法**：逐样本保存两侧 XYZ、UV、gap、alignment 和曲率比，并导出冲突点 BREP。

**效果与边界**：bearing 异常点两侧空间几乎重合，排除了远距离错误投影，更可能是局部主方向旋转或主曲率排序变化。

### 第 12 轮：冲突加密和方向矢量可视化

**问题**：单个异常样本可能只是噪声。

**方法**：初始 5 点出现冲突后自动加密到 21 点，并合并两批证据；导出两侧主方向矢量 BREP。

**效果与边界**：bearing 45–67 的冲突扩展为连续参数区间中的多个样本，证明不是孤立噪声，但在缺少真值时仍保留候选供复核。

## 五、第四阶段：Sewing 与变半径 R(s)

### 第 13 轮：受控 Sewing A/B

**问题**：Sewing 能修复断裂拓扑，也可能改变 pcurve、曲率采样和面连接，不能默认认为修复后更好。

**方法**：只在显式调用 `compareWithSewing()` 时对 Shape 副本 Sewing，同时返回原始和修复结果、面映射、边统计及 sewn BREP；不修改调用者原 Shape。

**效果与边界**：bearing 候选 41→153，hammer 15→0，影响方向完全相反。因此 Sewing 只能作为诊断 A/B，不能按候选数量自动择优。

### 第 14 轮：按 Solid/Shell 分区 Sewing

**问题**：对整个 Compound Sewing 可能把不同零件缝在一起。

**方法**：按 Solid 优先、Shell 次之分区，无归属散面才按空间邻近分区；建立有效性、面数、删除面、多重边、映射完整性安全门。

**效果与边界**：Motor 的 17 个壳和 CrankArm 的两个壳保持隔离。安全门只证明拓扑操作没有触发指定结构异常，不代表圆角候选准确。

### 第 15 轮：半径查询语义

**问题**：`minimumRadius/maximumRadius` 容易被误解为固定圆角半径。

**方法**：定义 nominal、entire、intersects、any 四种过滤模式，并为每条 Path 建立 RadiusProfile。

**效果与边界**：可以表达“名义值落入区间”“整个轮廓落入区间”“与区间有交集”或“不按半径过滤”。变半径的输入半径是查询条件，不是唯一设计半径。

### 第 16 轮：第一次恢复有序 R(s)

**问题**：只有最小/最大半径无法区分平滑渐变和突变。

**方法**：沿估计的圆角脊线方向采样 11 点，按三维弧长归一化为 `s∈[0,1]`，用总变差、有效变化步、单调性和主导单步比例分类恒定、平滑、分段和不连续。

**效果与边界**：OCCT 构造的 R=3→8 圆角得到约 3.115→7.887 的单调序列，被识别为平滑变半径候选。此时轨迹仍近似沿固定 U/V 参数行。

### 第 17 轮：主方向流线积分

**问题**：扭曲 BSpline 的 U/V 参数线可能横穿圆角截面，使截面曲率变化伪装成沿程变半径。

**方法**：把三维主方向解算成 UV 速度，从中部种子正反向做二阶流线积分；失败才回退参数线。轨迹与主方向最小对齐低于 0.90 时不进入路径 R(s) 分类。

**效果与边界**：linkrods 之前 5 条 segmented 被证明是采样方向错误，修正为恒定或证据不足。

### 第 18 轮：多种子、自适应缩步和尺度不变

**问题**：流线可能因大步跨越裁剪边界，也可能因把模型导入容差当作停机距离而在小尺度模型中完全无法前进。

**方法**：最多尝试 5 个种子；失败或方向对齐不足时缩小步长；覆盖率同时考虑样本数与实际 UV 长度；UV 度量奇异性使用无量纲判据；停机阈值使用数值精度。

**效果与边界**：bearing 的可追踪自由面全部使用主方向流线、零参数线回退；整体缩放到 `1e-4` 的变半径模型仍通过。

### 第 19 轮：跨圆角宽度的多流线稳定性

**问题**：单条流线可能恰好经过理想区域，不能代表整个圆角面的半径律。

**方法**：默认要求来自不同横向采样行的 3 条有效流线；按弧长重采样到共同位置并统一方向，比较对应位置半径，默认最大相对偏差 10%。

**效果与边界**：R=3→8 样件跨种子稳定；bearing 面 78 和 linkrods 面 24 暴露明显横向不稳定。非恒定行为只有通过稳定性门才能升级，否则降为证据不足。

## 六、第五阶段：全局路径、闭环和证据聚合

### 第 20 轮：路径规范方向与二状态动态规划

**问题**：逐面贪心翻转流线不能保证整条长链最优，闭环还需要考虑末面到首面的闭合关系。

**方法**：每个流线面只有“保持/反转”两种状态，转移成本由无量纲端点距离和有向主方向误差组成；动态规划寻找全路径最小成本。分叉路径规范为从分叉点向外，闭环用最小稳定 ID 选择根和环向。

**效果与边界**：19 条多流线轮廓执行全局优化，保证成本不高于贪心；此时闭环分支已实现，但还缺真实闭环运行覆盖。

### 第 21 轮：闭环、分叉真值件与精确修剪面距离

**问题**：需要真正执行闭环代码，同时周期底层曲面的宽包围盒可能让不相邻修剪面误连。

**方法**：生成四面闭合 BSpline 圆角环和全边圆角分叉箱体；包围盒只做预筛，复合连接必须再通过 `BRepExtrema_DistShapeShape` 的精确修剪面距离门。

**效果与边界**：闭环得到 4 面、4 活动 Link、1 个闭合 Path、44 个 R(s) 样本和恒定 R=5；修复了四节点环被误连成 K4 完全图的问题。

### 第 22 轮：逐方向转移证据

**问题**：路径总成本不能指出具体哪两个面出了问题。

**方法**：为每个相邻流线面输出归一化 gap、有向点积、成本、闭环 closure 和失败原因；中间夹有未采样解析面时记录 `unobserved-intermediate-faces`，不误判为直接冲突。

**效果与边界**：闭环 4 条转移全部通过；CrankArm 和 linkrods 的证据缺口被准确定位，强制阈值测试覆盖 gap 和方向冲突分支。

### 第 23 轮：Feature 三态证据和置信度

**问题**：一个置信度数字不能区分“明确发现冲突”和“只是缺少证据”。

**方法**：拓扑/支撑、半径稳定性和路径方向分别输出 `validated`、`conflict`、`insufficient-evidence`。最终置信度为基础几何置信度乘以三项加权分数，默认权重 0.40/0.30/0.30。

**效果与边界**：闭环样件三项全通过；bearing 明确分成 3 个冲突和 34 个证据不足 Feature，不再用同一个低分混淆两种情况。

### 第 24 轮：解析中间面方向桥接

**问题**：两个自由面流线之间可能隔着圆柱或圆环解析圆角面，导致方向证据长期缺失。

**方法**：沿路径逐跳检查解析圆角面的已有 Link 方向证据；全部兼容才通过，任一冲突则明确失败，缺 Link 保持未知。

**效果与边界**：混合解析/BSpline 闭环桥接通过；CrankArm 一个缺证连接补齐；linkrods 的 8 段不是被盲目放行，而是被确认存在方向冲突。

### 第 25 轮：缺口、错位、短边和薄片负样本

**问题**：极短边、极小薄片、修剪缺口和位置错位可能使算法把明显断开的几何重新连接。

**方法**：用边长/模型对角线和面积/对角线平方建立尺度归一分辨率门；短共享边 Link 不进图，并禁止后续复合连接绕过该门重新接回。

**效果与边界**：修剪缺口环不能闭合，错位面必须拆链，薄片严格门下产生 0 Feature，强制短边门能把闭环拆开；生产默认阈值不改变正常语料。

### 第 26 轮：解析桥有符号代价进入全局 DP

**问题**：第 24 轮是在全局方向已经选定后验证解析桥，动态规划本身仍不知道桥的真实连续性。

**方法**：沿“自由面—Link—解析面—Link—自由面”传播无向主方向轴的相对符号；圆柱和圆环内部用 12 步 UV 主方向场传播；真实跨边 gap 与 signed alignment 直接进入 DP。

**效果与边界**：混合闭环方向成本约 0.645→0.089，CrankArm 桥稳定通过；linkrods 的近零 signed alignment 仍保持冲突，没有被全局翻转掩盖。

## 七、第六阶段：准确率与工程性能

### 第 27 轮：面、链、Feature 三级真值评测

**问题**：候选数量不能衡量准确率，必须有独立的 FILLET/NOT_FILLET 真值。

**方法**：面级计算 TP、FP、FN、TN、precision、recall、F1；链和 Feature 转换成所属面 `persistent_id` 集合，用 IoU 建立候选匹配，再做一对一最大匹配。存在 UNKNOWN 或部分标注时禁用可能误导的对象级指标。

**效果与边界**：确定性闭环和 R=3→8 样件三级 F1 均为 1，证明评测链路和两个构造样件正确；真实工业模型尚无独立人工真值，不能声称真实准确率为 100%。

### 第 28 轮：阶段计时、Link 索引和性能预算

**问题**：需要知道时间花在哪里，并让性能退化可以进入自动回归。

**方法**：将 `recognize()` 拆成诊断、逐面分析、拓扑、半径/方向、Feature 五阶段计时；建立 `(faceA, faceB) → Link列表` 索引；提供完成后性能预算和 CLI 失败门。

**效果与边界**：linkrods 的面对查询候选访问量减少 95.7%；Debug 基线显示 bearing 最慢，约 28.6 秒。当前主要瓶颈是支撑恢复、拓扑构建和精确面距，不是最终 R(s) 聚合。正式 SLA 仍需 OCCT Release SDK。

## 八、第六轮 TopologyRole 专题详解

### 1. 角色来自候选连接图，不是曲面类型

算法只对已经接受的候选面建立图。两个面之间只有实际 `usedInGraph=true` 的 Link 才计入邻接；同一面对即使共享多条边，邻接集合中也只算一个邻居。

### 2. IsolatedPatch：度数为 0

```text
[A]
```

A 没有其他已接受圆角候选邻面。它可能是真实单面圆角，也可能因为邻面漏识别、IGES 拓扑断裂、半径过滤或自身误报而孤立。孤立不等于拒绝，但仅凭度数无法验证角色，所以当前 `roleConsistency` 保持 Unknown。

这里要区分同名概念：`TopologyRole::IsolatedPatch` 是单个面的局部角色；`FeatureKind::IsolatedPatch` 表示整个 Feature 只有一个面。

### 3. TerminalPatch：度数为 1

```text
[A] — [B] — [C]
```

A 和 C 各只有一个候选邻面，因此是 TerminalPatch。它们可能是真实开放圆角链端部，也可能是 Link 失败、漏识别或半径过滤造成的假终点。它不是“端盖面”，只表示在当前候选图和当前配置下度数为 1。端部几何可能是圆柱、BSpline 或双曲率终止补片，因此当前也不做强角色验证。

### 4. BandPatch：度数为 2

```text
[A] — [B] — [C]
```

B 有一个前驱和一个后继，处于路径中间。常见几何是圆柱、圆环、恢复圆柱或单主曲率自由曲面。算法会检查它是否具有 rolling-surface 几何；如果度数为 2却更像球面或双曲率角部，则标记 NeedsReview。

闭环中的每个面通常也都是 BandPatch：

```text
[A] — [B]
 |     |
[D] — [C]
```

四个节点的度数均为 2，但整个 Feature 是 ClosedLoop。这说明 Face 角色和 Feature 类型是两个层级。

### 5. JunctionPatch：度数大于 2

```text
        [B]
         |
[A] — [J] — [C]
```

J 同时连接三个候选邻面，因此是 JunctionPatch。它常见于三条边圆角汇合的角部补片，几何上通常像球面或双曲率 BSpline。算法要求 Junction 的几何最好属于解析/恢复球面或 `doubleCurved`；否则标记 NeedsReview。

Junction 也可能是假分叉：如果复合连接过多，本来每点度数为 2 的闭环可能被错误连成完全图。因此 JunctionPatch 是“需要结合几何复核的高图度节点”，不是自动确认的角部圆角。

### 6. 角色怎样形成 Path 和 Feature

简单链：

```text
Terminal — Band — Band — Terminal
```

通常得到 1 条开放 Path 和 1 个 SimpleChain Feature。

闭环：

```text
Band — Band
 |       |
Band — Band
```

得到 1 条闭合 Path 和 1 个 ClosedLoop Feature。

分叉网络：

```text
              Terminal
                 |
Terminal — Band — Junction — Band — Terminal
                 |
              Terminal
```

算法从度数不等于 2 的节点出发拆分最大非分支 Path。一个 Junction 面可能出现在多条 Path 中，但在 Feature 的面集合中只保存一次。最终整个连通分量成为 CompositeJunctionNetwork。

### 7. 集成时不能只看 TopologyRole

业务判断应联合使用：

```text
TopologyRole
+ RoleConsistency
+ externalSupportFaceIds
+ FeatureKind
+ topology/radius/direction EvidenceState
+ Feature confidence
+ RadiusBehavior
```

重点报告字段：

- `faces.csv`：`topology_role`、`role_consistency`、`role_reason`；
- `links.csv`：Link 是否 `used_in_graph`；
- `paths.csv`：分叉网络如何拆路径；
- `features.csv`：band、terminal、junction、isolated 面集合；
- `graph.dot`：直观检查节点度数和过连接。

## 九、28 轮后的能力和剩余边界

当前版本已经贯通解析/自由曲面候选、断裂支撑恢复、复杂链、闭环与分叉、变半径 R(s)、方向连续性、解析桥、负样本、三态证据、真值评测和性能预算。

仍不能直接称为企业量产最终版，主要原因是：

1. 真实工业模型尚缺足量、独立、交叉复核的人工真值；
2. 自由曲面 R(s) 是微分几何估计，不是 CAD 建模历史中的精确设计律；
3. IGES 散面的支撑恢复仍是误报和性能风险；
4. 当前性能是 OCCT Debug 基线，正式 SLA 需要 Release SDK；
5. 并行 OCCT 计算必须先验证 Handle、惰性缓存、线程安全和确定性。
